# 最后一次广播

洪水淹没了北岸。你是镇上最后一座电台的值班员许遥，只剩一块快耗尽的电池。一艘船、一面被雨撕破的校旗、两条都不能放着不管的频道。

## 开始

在仓库根目录运行（需要 Python 3）：

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

[在线试玩](https://detongz.github.io/last-signal-interactive/)或打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)。展开「频道附件」可以先看调度资料。开闸前可以先联系学校、水厂或救援艇。每通占两分钟，第一通可以安排提前行动，第二通只能核实情况；窗口关闭后仍可选开闸方案。每次选择和通话都会自动存档，重新打开页面可续玩；「重开」保留已解锁的结局记录。声音默认关闭。

首页的「立即开船」可直接试玩救援艇，不影响剧情存档。进入剧情后，第一次广播抉择也会切到救援艇关卡。用方向键、WASD 或屏幕上的方向按钮驾驶。两箱物资要分两趟送，注意会推船的水流和有限燃油。燃油耗尽后可重试，也可带着实际送达结果继续。两条路线使用不同航道，故事共有四个结局。

## 技术和验证

方格地图和移动操作参考了 [klevze/sokoban（MIT）](https://github.com/klevze/sokoban)。救援艇规则、地图、美术和剧情为本作编写。

原生 HTML、CSS、JavaScript 模块。剧情内容在 `story.js`，分支与存档校验在 `engine.js`，界面和可选的 Web Audio 雨声在 `app.js`。不用安装运行依赖，不需要 API 密钥或远程服务。

安装 Node.js 18 或更新版本后，运行 `npm test`。测试覆盖四个结局、三方联络顺序对时间的影响、通话上限及无效存档。

## AIGC 和素材

- **OpenAI Codex（GPT-6.2）**参与原创脚本、分支设计和实现。先确定两个决定及其共同后果，再编写各路的证据、场景和独立尾声。
- **OpenAI ImageGen** 根据美术分镜生成一张四格静帧，覆盖塔外、值班室、闸底和雨后。压缩后的 WebP 随仓库交付，四个画面共用一张预加载图片。
- 雨声使用 Web Audio 在浏览器合成。故事、人物与地点均为虚构，没有外部视频、音乐或字体素材。制作步骤、提示词与取舍见 [AIGC 制作笔记](docs/aigc.md)。

## 已知限制

画面是静态分镜，角色无线电对白为字幕。浏览器音频不可用时仍可游玩。存档仅保留在当前浏览器，可清除站点数据重置。关卡送达结果会随剧情保存，航行中刷新会从码头重新出发。手头的短篇体量不覆盖题面建议的半小时单周目。
